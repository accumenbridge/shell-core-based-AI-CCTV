# Veyviz becomes a consumer, not the neutral core

No existing Veyviz source, branch, schema, permission, release, camera, model or deployment was changed by this delivery. The previous spatial source bundle is not applied here. This independent repository requires no private Veyviz checkout to run.

| Existing Veyviz area | Disposition |
|---|---|
| Workspace lifetime / registered contribution ideas | Reusable design inputs. These new neutral APIs are not claimed to be ABI-compatible extractions. |
| Site/floor/camera context, spatial payloads, Topology clients | Keep in the physical-operations family. Do not add mandatory fields to neutral RequestContext/WorkspaceContext. |
| Existing CapabilityPack catalogue / tenant plan authority | Preserve. A future adapter can supply neutral composition material without creating a competing Veyviz entitlement catalogue. |
| Alerts, staff Work, evidence and Forensics records | Preserve current owners. Do not migrate them into the reference Service Desk or Knowledge tables. |
| Current React/Nest clients and services | Preserve. Integrate host seams through explicit adapters after source reconciliation. The local Node/DOM profile is not a replacement command. |
| Video, Intel/OpenVINO and source supervision | Optional specialized runtime family. No dependency of neutral startup. |
| Existing operational releases | Follow their actual compatibility and deployment process. This prototype is not installed there. |

## Bounded adoption path

First compare exact public contract/lifetime requirements against current source. Identify one truly neutral seam and a compatibility adapter. Test old and new consumers against it. Keep existing authoritative state and authentication in place. Move a reusable implementation only after the actual source/dependency boundary is verified; do not mass-rename folders or move persistence to make this repository look complete.

The initial reference products are intentionally different from CCTV. They reveal neutrality defects without making Veyviz responsible for proving every new framework convention. They do not replace the later Veyviz source, model, hardware, permission and end-to-end qualification work.
