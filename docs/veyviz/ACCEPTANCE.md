# Local release acceptance

No new-product implementation or verification is accepted by this document. Qualification is candidate/profile-specific.

| Criterion | Required evidence | Initial state |
|---|---|---|
| Independent construction | New repo installs/builds from its captured Node/Python closure; no original checkout runtime imports | NOT_RUN |
| Scoped product ownership | Actual source registration, persisted job/result owner operations, two-tenant denial and object-scope tests | NOT_RUN |
| Real model execution | Real RF-DETR CPU executes three sampled frames from actual recording bytes; exact asset/model/code hashes retained | NOT_RUN |
| End-to-end browser | Actual authenticated browser registers/selects recording, starts analysis and displays typed returned results | NOT_RUN |
| Authority preservation | Verified original actor/scope/command identity through adapter and result adoption; revocation/duplicate/conflict cases | NOT_RUN |
| Durability and lifecycle | Normal stop/restart preserves results; launched native work has actual owned close evidence | NOT_RUN |
| Extensibility | Two exact product variants run with reviewed contributions without modifying framework hosts | NOT_RUN |
| Fresh regression | Source build, npm test and installed Python tests with actual outputs and explicit skips/blocks | NOT_RUN |
| Independent review | Separate reviewer checks exact source diff and evidence for the final candidate | NOT_RUN |

Three-frame sampling proves a bounded recording-analysis workflow; it does not prove continuous CCTV, temporal tracking or detection accuracy. Record model licensing/redistribution constraints when actually inspected; do not copy secrets or silently download/enable providers.

Root must freeze complete product implementation and test paths in the structured task contract before writer admission/acceptance. Initial governance hashes alone cannot qualify product code. Reconcile changed files explicitly and preserve failed attempts.
