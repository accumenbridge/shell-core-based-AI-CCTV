## Outcome

Expose three versioned, executable Knowledge owner operations through ApplicationHost: `knowledge.documents.search` version 1, `knowledge.documents.get` version 1 and `knowledge.documents.create` version 1. Search/get require knowledge.read/read; create requires knowledge.write/write and a stable command ID. No MCP, new HTTP endpoint, iframe, plugin installer or arbitrary route dispatcher in this increment.

The current host already constructs trusted RequestContext and checks original authorization before and after awaited route handlers. The new operation dispatcher must reuse that authority and the same owner command implementation, rather than create a grant resolver. The existing factory exports selected module/package files via the fixed workspace closure; no new package resolver is needed.

## Neutral contracts and dispatch

Add optional `ModuleManifest.operations` declarations. Legacy manifests and HostedModule registrations with no declarations/handlers remain valid. Each declaration contains id, integer version, title/description, permission, kind, inputSchema and outputSchema. An executable registration contains its exact declaration and a reviewed `handle(ctx,input,commandId?)` function. IDs are module-qualified; identity is the `(id,version)` pair, not a method/path. Declaration metadata is discoverability, never authorization.

Implement a documented JSON Schema subset, not a claim of a full validator: object/properties/required/additionalProperties:false; string/minLength/maxLength/pattern; integer/minimum/maximum; boolean; array/items/maxItems; enum. Reject unsupported keywords, malformed schemas and cyclic/non-JSON inputs. Keep schema/instance traversal bounded; publish the actual subset. Initial operation schemas need no references, combinators, coercion, defaults or dynamic resolution. Suggested fixed profile: depth 8, 32 properties per object, schema 16KiB, input 512KiB and output 128KiB. Treat these as serialized UTF-8 byte limits separately from string lengths. Do not add a validator dependency solely for these three schemas.

ApplicationHost constructor validates all selected declarations and exact handler parity (including permission/kind/schemas), rejects missing/extra handlers and collisions, and captures immutable descriptor copies. `operationCatalogue(actor,tenant,originalAuth?)` exposes descriptor data only for selected, currently authorized operations; it exposes no function/store/path. `invokeOperation(id,version,trustedActor,trustedTenant,input,commandId?,signal,requestId,originalAuth?)` is the fixed trusted transport seam. Input has no actor/tenant/product/instance authority fields. Require READY, exact selection, schema validation, and existing context.assertAllowed before invocation and after await. Recheck original session on rejected await too; cancellation suppresses returned late output. Write command IDs are required and bounded; requestId is not an idempotency key. Never replace a committed owner write with a claimed rollback when a later session check denies its response; retry uses the same owner command ID.

Composition validates descriptor shapes, module ownership, declaration of the permission and global identity collisions. SDK defineModule uses the same pure descriptor validator. No neutral package imports Knowledge, no executable import URL or route-name-to-function lookup.

## Knowledge owner implementation

Move the current search SQL and document creation command into named module-owned functions reused by HTTP routes and operation handlers. Preserve `knowledge.document.read.v1` and retrieval/answer contracts and all migrations. The existing read.v1 get remains compatible for Handoff; the new bounded get is an explicit projection, not a replacement that breaks Handoff.

- Search `{query}`: retain existing bounded query/token handling; return at most 25 indexed READY records belonging to ctx.tenantId, each id/title/version and an explicitly capped excerpt (e.g. 512 characters), plus INDEXED_DOCUMENTS_ONLY coverage. Join the owner documents table for current state/version. No raw FTS/body/job/database rows. HTTP route and executable operation call the same search function.
- Get `{documentId}`: tenant-scoped owner read; return id/title/version/state, a bounded body excerpt (e.g. 4096 characters), `truncated` and full-body digest. No job internals, path, credential or another tenant's resource. Keep the output schema finite and match actual owner states.
- Create `{title,body}`: preserve current 200/64000 string bounds and exact existing `store.command(ctx,'knowledge.add',commandId,{title,body},'knowledge.write',...)`, enqueue and document transaction. Same actor/scope/key/input across HTTP and operation must replay one document/job; different input conflicts. Return the existing bounded create receipt. Construct/validate this DTO within the owner transaction if validation can fail after mutation. Never await inside the transaction.

Each owner entry point asserts its permission; handlers are not safe merely because one host caller checks it. Invocation adds the host's original-session/cancellation reconciliation. This is trusted reviewed code, not an untrusted plugin sandbox.
