Destination and policy

Destination: Build and operate reviewed products through a product-neutral Studio, with exact composition, immutable artifacts, domain ownership and understandable user journeys.

Users

  • Product developer
  • Local platform operator
  • Domain application user
  • Project owner reviewing direction and delivery

Non-goals

  • Changing the external Veyviz repository
  • Universal domain data ownership
  • Arbitrary executable import strings
  • Unapproved credentials, spending or deployments
  • Claiming production or bug-free status from local checks

Success signals

  • Core journey acceptance: Candidate-specific demonstration of each required user journey with blocked and unrun checks retained. Baseline: unknown · Target: unknown
  • Delivery cycle time: Elapsed time from agreed ready point to accepted core outcome, reporting blocked time separately. Baseline: unknown · Target: unknown
  • Review rework: Revisions after a defined independent review point, with causes. Baseline: unknown · Target: unknown
  • Escaped defects: Confirmed defects discovered after the defined acceptance boundary and exposure window. Baseline: unknown · Target: unknown

Working policy

Core first: Finish the next coherent user journey and its essential correctness before speculative breadth. Current execution selection comes from .brain/CURRENT.md, not a copied next-action label. · WIP limit: 1

Review cadence: Before a bounded milestone starts · After source or contract change that affects the plan · After actual check or review results · At a user-visible milestone demonstration · At a meaningful drift or repeated-failure finding

Non-negotiables: Keep neutral packages independent of domain modules and product wiring. · Preserve actor/product/instance/tenant/command identity and owner databases. · Build before source tests; preserve failed, blocked and unrun evidence. · Offline views gain no filesystem/build privileges. · Existing source catalogues remain authoritative; this atlas is not an allowed-module list.

Defer rule: Defer optional polish, speculative generalization and unrelated edge campaigns with a reason and revisit trigger. A concrete violation of the current outcome or essential invariant stays core.
