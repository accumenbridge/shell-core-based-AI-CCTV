# PLATFORM-005 planning proposal — not adopted or implemented

Sol/high source-grounded read-only planning while CP4 implementation proceeds. CP4 acceptance is prerequisite; current mapped work remains PLATFORM-004. This proposal does not qualify hosted identity/storage or change whole-program acceptance.

Source already supplies AccessPort, HttpAccess and asynchronous JobExecutionStore. Maintained runtime selects LocalAccess; each domain constructs its own SqliteOwner from ModuleEnvironment.dataPath. Universal PostgreSQL repository replacement would violate owner boundaries. Hosted production/OIDC requires an explicit target profile not yet specified.

Candidate first local slice (PLATFORM-005A): verified backup and entirely empty-destination restore of one positively stopped exact managed instance. App-local runtime-recovery/fixed helper, additive runtime maintenance/backup identities and durable slot, runtime restart fences, fixed paired API/Studio. No domain schema/grant/ABI edits. Capture exact artifact/profile/config/enrollment, original actor/key and owner/migration identities; synchronous after-BEGIN session/maintenance guards prevent concurrent restart. UNKNOWN keeps reservation; no PID/time release.

Derive access plus selected module databases from the exact plan. Include required private enrollment/config; never disclose contents/credentials in HTTP. Consistent SQLite backup into fresh staging, not main-file copy that may omit WAL. Verify integrity, _owner, access instance and migration metadata. Publish bound immutable digest inventory with reviewed nonreplace mechanism; audit/logout/crash failures retain original physical facts without false advertised success. Official references reviewed by planner: https://www.sqlite.org/backup.html and https://nodejs.org/api/sqlite.html#sqlitebackupsourceDb-path-options. Node backup destination can overwrite, so destination must be fresh owned staging.

Restore only same exact instance with an entirely absent data tree. No overwrite/merge/purge/domain transfer/reseed/start; fully verify backup and privately stage before nonreplace publication. Separately confirmed runtime restart follows successful restore. Different-instance transfer requires owner-specific contract. Proposed fixed bounds32MiB/owner,128MiB/backup,32backups/512MiB aggregate, one physical recovery slot and current metadata/path budgets; recovery bounds do not cap domain writes. Conservative staging/UNKNOWN accounting; no automatic purge.

Proposed fixed instance backup list/create, backup detail/verify and restore envelope {confirm:true,backupId,requestKey}; no client paths/SQL/executable/URL/credentials/destination. Public bounded metadata/facts only. Actual tests should cover Service Desk records, grant/principal revocation retention, Combined document/index/job/Handoff receipts, WAL-only committed data, mismatched owner/migration/artifact/config, nonreplace existing file/link/data, two-process maintenance/runtime fencing and original-session/audit/crash failures. Only fixture-owned original data may be removed by a restore test.

Later PLATFORM-005B hosted seams: independent access/execution-store conformance with actual tenant/actor/mode/revocation/stale-commit negatives; fixed trusted issuer OIDC fixture maps subjects to independently owned grants. Claims cannot invent permissions. Actual hosted selection needs issuer/organisation model, grant administrator, database/provider target and recovery objectives. No external repository/credential/config/spending/deployment action authorized by this proposal. No implementation/test/browser/production pass claimed.
