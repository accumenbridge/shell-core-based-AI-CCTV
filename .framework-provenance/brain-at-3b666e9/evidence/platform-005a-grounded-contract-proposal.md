## Read-only owner refinement — still NOT ADOPTED

Sol inspected the maintained LocalAccess and SqliteOwner owners. LocalAccess authenticates only sessions whose expires value exceeds the current clock and whose principal remains active with user kind. Logout deletes the supplied session token only; no canonical bulk invalidation seam exists. Proposed supported local backup eligibility therefore requires zero unexpired access sessions in the verified snapshot at a bound verification time. Restore requires current time at least that recorded verification time; expired session rows remain unchanged. Users can log out before stopping or wait for the existing one-hour sessions to expire. This avoids resurrecting a session without generic recovery code mutating another owner's access tables. Backups with active sessions would need a separately implemented canonical owner recovery contract. This proposal does not alter an existing credential or grant.

Exact plan module schema envelopes and registered artifact inventory are available. SQL migrations remain inside constructors/create functions, with no pure migration descriptors. Read-only verification can assert expected owner, contiguous captured migration history, exact binding and current schema envelope against the same immutable artifact. It cannot independently assert migration SQL digest compatibility. A separate canonical same-artifact restart remains the final compatibility check; no constructor probe, source-text execution, or exported-copy patch is proposed. Local clock monotonicity is a supported-profile constraint, not hostile-clock resilience. CP4 matching acceptance remains prerequisite to adoption and coding.
